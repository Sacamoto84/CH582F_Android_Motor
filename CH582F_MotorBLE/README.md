# CH582F — контроллер помпы для 19-литровой бутыли + BLE

Перенос [CH32V003_MotorControl_Volume](https://github.com/Sacamoto84/CH32V003_MotorControl_Volume)
на CH582F. Логика та же: **потенциометр задаёт мощность напрямую, при старте
даётся рывок**. Добавлено BLE для настройки и телеметрии, плюс сон.

Плата WeAct CH57x/CH58x Core Board V1.0, аккумулятор 1S Li-ion, мотор 0.7 А,
ключ AO3400.

**Схему, номиналы и распиновку смотри в [HARDWARE.md](HARDWARE.md).**
**Задание на Android-приложение — в [ANDROID_APP_TASK.md](ANDROID_APP_TASK.md)**
(самодостаточный документ: протокол, параметры, сценарии).

⚠️ **Незакрытые проблемы — [ISP_AND_DEBUG.md](ISP_AND_DEBUG.md):**
не получается войти в ISP-загрузчик, плохо работает отладчик.

## Чего в проекте намеренно нет

Бездатчиковый контроль оборотов по противо-ЭДС с ПИ-регулятором (как в
[AlexGyver/DrillPID](https://github.com/AlexGyver/DrillPID)) был реализован
и **удалён**.

У помпы нагрузка постоянная: просадка оборотов одинакова от раза к разу и
компенсируется один раз положением ручки. Клинить нечему — это не сверлильный
станок. Регулятор решал бы несуществующую проблему, а тащил за собой два
делителя, конвейер измерения на прерываниях ADC+TMR, ПИ с антивиндапом,
две процедуры калибровки и десяток параметров.

Осталось то, что реально нужно.

## Автомат состояний

```
        ┌────────┐  старт (кнопка / BLE)   ┌─────────┐
        │ M_IDLE │ ──────────────────────> │ M_BOOST │
        └────────┘                         └────┬────┘
             ▲                                  │ boost_time
             │                                  ▼
             │   стоп / max_run_s / vbat   ┌─────────┐
             └──────────────────────────── │  M_RUN  │
                                           └─────────┘
```

| Состояние | Скважность |
|---|---|
| `M_BOOST` | `max(boost_power, ручка)`, частота `pwm_freq_boost` |
| `M_RUN` | ручка, отображённая в `pwm_min … pwm_max`, частота `pwm_freq_run` |

`boost_power` — **абсолютная** скважность рывка, не добавка: он должен пробить
трение покоя и столб воды независимо от того, куда выкручена ручка.

Защита одна, выключается нулём: `max_run_s` — авто-стоп. Бутыль опустела,
помпа гонит воздух — незачем.

**Отсечки по разряду аккумулятора нет намеренно.** Помпа работает при любом
напряжении банки, пока живо питание МК. Напряжение меряется и уходит в
телеметрию, но ни на что не влияет.

Проект самодостаточный: SDK скопирован внутрь, никаких linked resources.

  motor_task.c                  задача TMOS: АЦП, автомат, кнопка, телеметрия
  pwm_motor.c                   ШИМ на PWMX → PB7
  buzzer.c                      пищалка на PB4, тон через прерывание TMR1
  settings.c                    параметры в DataFlash, два слота
  peripheral.c                  роль GAP Peripheral
  include/
    board.h                     распиновка

**`HAL/include/config.h` удалён намеренно.** Windows не различает регистр,
поэтому `#include "CONFIG.h"` из `HAL.h` резолвился бы то в наш файл, то в
штатный. Один файл конфигурации, `APP/include/CONFIG.h`, снимает вопрос —
там же полный переведённый справочник всех опций стека.

## Протокол BLE

Сервис `0xFFE0`, два характеристика:

| UUID | Свойство | Назначение |
|---|---|---|
| `0xFFE1` | write | команда `[op][lo][hi]`, 3 байта |
| `0xFFE2` | notify | телеметрия, ответы, квитанции |

`op`:

| Значение | Действие |
|---|---|
| `0x00…0x7F` | записать параметр с этим id, значение uint16 в `[lo][hi]` |
| `0x80` | прочитать параметр, id в `lo`; ответ в notify |
| `0x81` | команда, код в `lo` |
| `0x82` | выгрузить все параметры серией notify |

Всё влезает в 20 байт, поэтому работает при MTU по умолчанию — согласование
не требуется.

Выгрузка по `0x82` идёт по одному параметру за тик задачи мотора
(`MotorService_DumpTick`), а не циклом. Очередь стека — `BLE_BUFF_NUM = 5`
пакетов, за одно событие соединения радио выпускает `BLE_TX_NUM_EVENT = 1`;
цикл прокручивался за микросекунды и терял хвост серии. Теперь пакет, который
не влез, повторяется на следующем тике, и темп сам подстраивается под интервал
соединения.

### Параметры

| id | Имя | Единица | Дефолт |
|---|---|---|---|
| 0 | `PWM_MIN` | промилле | 300 |
| 1 | `PWM_MAX` | промилле | 950 |
| 2 | `PWM_FREQ_RUN` | Гц | 16000 |
| 3 | `PWM_FREQ_BOOST` | Гц | 1000 |
| 4 | `BOOST_EN` | 0/1 | 1 |
| 5 | `BOOST_POWER` | промилле, абсолютная | 800 |
| 6 | `BOOST_TIME` | мс | 150 |
| 7 | `MAX_RUN_S` | с, 0 = выкл | 120 |
| 8 | `VBAT_SCALE_Q12` | Q12, калибровка делителя | 4666 |
| 9 | `VDROP_LEVEL` | сброс по просадке: 0 выкл, 1=1.9 2=2.1 3=2.3 4=2.5 В | 4 |
| 10 | `SLEEP_TOUT_S` | с, 0 = выкл | 60 |
| 11 | `VBAT_MIN_MV` | мВ, отсечка по разряду, 0 = выкл | 3000 |

### Команды

`0` стоп, `1` пуск, `2` сохранить в DataFlash, `3` сброс к заводским,
`4` уснуть, `5`/`6` телеметрия вкл/выкл.

**Запись параметра во flash не попадает.** Значение применяется в ОЗУ сразу —
частота ШИМ слышна на ходу, скважность меняется на следующем тике, — но
переживёт сброс только после `CMD_SAVE`. Так подбор в мастере не стоит ни
одного цикла стирания страницы.

`CMD_SAVE` на работающей помпе отвечает `status = 1` и ничего не пишет:
стирание страницы блокирует ядро на единицы десятков мс, за это время выход
ШИМ застынет, а BLE потеряет пачку connection event. Сначала стоп, потом
сохранение.

Исключение — `CMD_FACTORY_RESET`: он взводит отложенную запись сам, потому
что сброс к заводским подразумевает сохранение.

Калибровка `VBAT_SCALE_Q12`: измерь банку мультиметром, посмотри `vbat_mv`
в телеметрии, новое значение = `старое * реальные_мВ / показанные_мВ`.

### Телеметрия

10 байт, little-endian, раз в 200 мс после `CMD_TELEMETRY_ON`:
`type, state, stop_reason, pwm_pct, pwm_pm, pot_raw, vbat_mv`.

Поле `stop_reason`: 0 — не останавливались, 1 — пользователь,
2 — сработал `max_run_s`, 3 — пуск отклонён отсечкой по разряду.

Проверять удобно из nRF Connect: подключиться к `MotorCtrl1`, включить
уведомления на `0xFFE2`, писать 3 байта в `0xFFE1`.

## Порядок настройки под свой мотор

1. `BOOST_EN = 0`, ручка на минимум. Поднимай `PWM_MIN`, пока помпа не начнёт
   **уверенно держать** вращение.
2. `BOOST_EN = 1`. Поднимай `BOOST_POWER`, пока не будет **уверенно трогаться**
   с ручки на минимуме. Это порог трения покоя плюс столб воды.
3. `BOOST_TIME` — минимальное, при котором успевает раскрутиться. Обычно
   100–200 мс.
4. `PWM_FREQ_RUN` — 16 кГц выше слышимого. Если помпа свистит, попробуй
   20–25 кГц; ниже 919 Гц PWMX не умеет.
5. `MAX_RUN_S` — сколько секунд занимает налив самой большой кружки, плюс запас.
6. `VBAT_SCALE_Q12` — по мультиметру, один раз.

## Кнопка

Кнопка K2 «BOOT» платы, PB22. Автомат — порт `uButtonVirt.h` из проекта на
CH32V003, тайминги один в один, чтобы поведение для пользователя совпадало.

| Действие | Что делает | Звук |
|---|---|---|
| **Нажатие** (сразу, не по отпусканию) | **триггер: пуск / стоп** | `ios_click` 1800/25 |
| **Удержание 5 с** | сигнал, затем **сброс чипа** | `shutdown` 1200→900→600 |

Сброс пятью кликами убран: удержание делает то же самое, а два пути
к перезагрузке — просто лишний способ попасть туда случайно. Вместе с ним
из автомата ушёл счётчик кликов с окнами накопления и таймаута — настройка
без экрана, ради которой он существовал, переехала в BLE.

### Как попасть в ISP-загрузчик

**Программным сбросом — никак.** В `R8_GLOB_CFG_INFO` бит `RB_BOOT_LOADER`
документирован как «0 = application status (by software reset)»: при
программном сбросе чип по определению уходит в приложение, пин BOOT при
этом не читается вообще. Его опрашивает загрузочный ПЗУ, а тот отрабатывает
только при настоящей подаче питания (RPOR) и внешнем сбросе (MR).

Документированного софтового пути в ISP нет. В своём OTA сам WCH делает
программный сброс не в ПЗУ-загрузчик, а в собственный IAP, лежащий
в пользовательском флеше.

**Правильное решение — включить вывод сброса.** Кнопка K1 на плате мертва
с завода: `CFG_RESET_EN` по умолчанию 0 (даташит, табл. 2-3). Включается
галкой в WCH-LinkUtility, в настройках байтов конфигурации. После этого
работает штатная процедура:

> зажать K2 (BOOT) → нажать и отпустить K1 (RST) → отпустить K2

Через `UserOptionByteConfig()` из кода то же самое сделать можно, но WCH
предупреждает, что после её вызова двухпроводной отладочный интерфейс
выключается — а с ним и так непросто. Только утилитой.

Удержание кнопки сейчас делает сброс сторожевым таймером (WTR), а не
программный. Это отдельный тип сброса, и комментарий SFR его не исключает —
есть шанс, что ПЗУ отработает его с опросом PB22. **Не документировано**,
надежда слабая, но попытка бесплатная.

Тайминги: дебаунс 10 мс, удержание 5000 мс. Больше в автомате ничего нет.

Считать надо не до начала сигнала, а до его конца: сброс происходит, когда
домолчит пищалка (`s_reboot_armed && !Buzzer_IsBusy()`), иначе тон оборвался бы
на середине. Мелодия `shutdown` длится 480 мс, то есть от нажатия до сброса
проходит около 5.5 с. Именно в этот момент ПЗУ-загрузчик читает PB22 —
отпустили раньше, стартует приложение.

«Лестница» импульсов удержания из оригинала выброшена вместе с четырьмя
экранами настройки (`SET_POWER`, `SET_BOOST_ENABLE`, `SET_BOOST_POWER`,
`SET_BOOST_TIME`) — эти параметры теперь в BLE.

Уход в сон в оригинале делал `b.timeout()` через секунду после отпускания.
Здесь этим занимается таймер простоя `SLEEP_TOUT_S`, который заодно
учитывает открытое соединение BLE.

**PB22 — это пин ISP-загрузчика.** Нажатая кнопка в момент подачи питания или
сброса уводит чип в загрузчик, программа не стартует. Плюс первые
`BOOT_DELAY_MS` миллисекунд после сброса `main()` стоит в глухой задержке и
кнопка не опрашивается. Если «кнопка не работает» — проверь сначала это.

## Защита от просадки питания

Мотор 0.7 А роняет банку на старте, и чип может зависнуть, не дойдя до порога
аппаратного сброса. Четыре независимых механизма:

| Механизм | Порог | Что делает |
|---|---|---|
| **Отсечка по разряду**, `VBAT_MIN_MV` | **3.0 В** на банке, настраивается | не даёт запустить помпу |
| **LVR**, аппаратный | 1.8 / 2.05 / 2.3 В, **не настраивается** | полный RPOR |
| **Детектор VDD33**, `VDROP_LEVEL` | 1.9 / 2.1 / 2.3 / **2.5** В | NMI → программный сброс |
| **Сторожевой таймер** | 559 мс без кормления | сброс |

Первый механизм работает по **банке**, остальные три — по **VDD33 после LDO**.
Не путать: `VBAT_MIN_MV` смотрит на 3.0…4.2 В аккумулятора, `VDROP_LEVEL` —
на 1.9…2.5 В питания ядра.

### Отсечка по разряду

`VBAT_MIN_MV` — единственная защита, которая срабатывает **до** проблемы,
а не разгребает последствия. Ниже порога `Motor_Start()` возвращает 0:
помпа не запускается ни с кнопки, ни по BLE, играет `buzzer_error()`,
а в телеметрию уезжает `stop_reason = 3`, чтобы приложение объяснило отказ.

Сравнение идёт с последним замером vbat, а он делается раз в 2 с при
**стоящей** помпе — то есть без нагрузки, по честному напряжению покоя.

Уже работающую помпу порог не глушит. Под 0.7 А банка проседает на десятые
доли вольта, и отсечка по мгновенному значению вырубала бы насос через
секунду после каждого пуска. Дальше по разряду работает `VDROP_LEVEL`.

`0` выключает отсечку совсем. Потолок 4200 мВ — заряженная банка 1S столько
и даёт, порог выше сделал бы помпу неработоспособной навсегда.

Про LVR: даташит табл. 20-2, строка «Non-CH583X». Порог зашит в кремний.
Между банкой и чипом стоит LDO, поэтому при просадке банки 3.7 → 3.0 В на
VDD33 остаётся ~2.9 В — до LVR далеко, а ядро уже виснет. Отсюда и зависание
вместо сброса.

Детектор ловит раньше. Уровень 4 (2.5 В) выбран дефолтом: он единственный
гарантированно выше максимума LVR (2.3 В), то есть сработает до него.
Детектор ест 210 мкА, поэтому включается только на время работы помпы.
Обработчик `NMI_Handler()` в `main.c` гасит ключ прямо регистрами и делает
программный сброс.

Сторожевой таймер работает всегда и ловит зависание любой природы. Счёт
Fsys/131072 = 2.18 мс на такт, переполнение 8 бит даёт 559 мс. Кормится
в тике задачи каждые 10 мс.

**Причина последнего сброса печатается в UART при старте** — `reset: WDOG`
означает зависание, `reset: RPOR` — подачу питания или срабатывание LVR.
Это главный инструмент при ловле просадок.

Если сбрасывается на каждом пуске — проблема в железе, лечится
конденсаторами, а не порогом. Смотри [HARDWARE.md](HARDWARE.md).

## Отладка: `DEBUG_FRIENDLY`

Три механизма выдёргивают чип из-под WCH-Link:

1. **Сторожевой таймер.** На точке останова ядро стоит, а таймер считает
   и через 559 мс сбрасывает чип. Отладка становится невозможной.
2. **Глубокий сон.** Ядро обесточивается, отладчик теряет цель насовсем.
3. **Детектор просадки VDD33.** Даёт NMI и сброс, в том числе на бросках
   тока при прошивке.

Переключатель в `board.h` гасит все три:

```c
#define DEBUG_FRIENDLY  1    /* 0 в рабочей прошивке */
```

Сейчас стоит `1`. **В рабочей прошивке обязательно ставить `0`** — там эти
механизмы нужны, особенно сторожевой таймер против зависаний от просадки
питания при пуске мотора.

## Про сон

Используется `LowPower_Shutdown`, а не `LowPower_Sleep`.

| | Sleep | Shutdown |
|---|---|---|
| Ток | 0.7…2.8 мкА | 0.2…2.3 мкА |
| После пробуждения | `__WFI()` возвращается | PMU делает GRWSM-сброс, старт с `main()` |
| Восстанавливать вручную | тактовую, АЦП, RF | ничего |

Выбор не ради микроампер, а ради того, что восстанавливать нечего: программа
стартует заново, как при `PWR_EnterSTANDBYMode` на CH32V003. Настройки лежат
в DataFlash.

### Две разные спячки

| | Кто усыпляет | Когда | Что останавливается |
|---|---|---|---|
| **Автосон стека** (`HAL_SLEEP`) | `CH58X_LowPower()` из HAL | между событиями BLE, куски по ~10 мс | PLL и HSE, а с ними **PWMX и TMR1** |
| **Глубокий сон** | `Board_Sleep()` → `LowPower_Shutdown()` | простой `SLEEP_TOUT_S` | всё, с последующим сбросом |

Автосон опасен для мотора: счётчик PWMX тактуется от Fsys, при остановке
такта выход застывает на текущем уровне. «Застывание в единице» держит ключ
полностью открытым весь сон. Тон пищалки от прерываний TMR1 по той же
причине рвётся.

Поэтому в `HAL/SLEEP.c` добавлен крючок `App_SleepAllowed()` (слабая
заглушка разрешает всё), а `motor_task.c` даёт сильную версию:

```c
uint8_t App_SleepAllowed(void)
{
    if(s_state != M_IDLE)  return 0;    /* ШИМ замер бы вместе с Fsys */
    if(Buzzer_IsBusy())    return 0;    /* тон порвался бы            */
    return 1;
}
```

**Пока помпа работает, чип не спит вообще.** Ни автосном, ни глубоким.
Это же стабильное окно для отладчика. Ток МК на фоне 0.7 А мотора не виден.

### Когда чип уходит в глубокий сон

Все три условия одновременно:

```
помпа стоит (M_IDLE)
  И никто не подключён по BLE
  И прошло sleep_tout_s без активности
```

`CMD_SLEEP` — отдельная дорога: он усыпляет сразу и работает даже при
`sleep_tout_s = 0`.

**Пока помпа работает, чип не спит вообще.** Таймер простоя сбрасывается
каждый тик, и то же состояние проверяется в самом условии — двойная защита.
Это и есть окно, в которое удобно цепляться отладчиком: запустил насос и
подключайся.

Отсчёт сбрасывает любая активность: пуск, стоп, нажатие кнопки, пакет по BLE,
подключение телефона. Открытое приложение держит устройство бодрым бесконечно.

Пробуждение — кнопкой PB22. Перед засыпанием гасится реклама BLE и даётся
200 мс, чтобы стек доработал свои RTC-события, иначе он сразу разбудит чип.
Если в эти 200 мс что-то произойдёт, засыпание отменяется и реклама
включается обратно.

### Как перезалить уснувшую прошивку

В Shutdown ядро обесточено и WCH-Link к чипу не цепляется. Раньше от этого
страховал параметр `BOOT_GRACE_S` — окно после сброса, в течение которого сон
был запрещён. Он **убран** (версия настроек 8): проект заливается через
ISP-загрузчик, а это ровно тот способ, ради обхода которого окно и держали.

Заодно ушёл его побочный эффект: во время окна блокировался не только глубокий
сон, но и автосон стека BLE — все 30 секунд после каждого включения чип
потреблял заметно больше.

Порядок заливки: удержать кнопку до сигнала и **не отпускать** — PB22 в момент
сброса низкий, стартует ISP-загрузчик. Подробности в
[ISP_AND_DEBUG.md](ISP_AND_DEBUG.md).

`BOOT_DELAY_MS` в `board.h` (сейчас 0) — глухая пауза в начале `main()` до
настройки пинов. Спасает, если прошивка падает позже старта, но от засыпания
не защищает.

### Свободные ножки

Про сон говорить бессмысленно, если незанятые ножки висят. После сброса все
GPIO — входы без подтяжек: потенциал болтается около порога переключения,
оба транзистора приёмника приоткрыты, и через него течёт сквозной ток, единицы
микроампер на пин. Чип в Shutdown потребляет 0.2 мкА, так что одна висящая
ножка перекрывает весь бюджет. Рядом ещё ключ мотора на 0.7 А — висящий вход
ловит его наводку, и ток гуляет вместе с ней.

**Замерено после наведения порядка: 0.8 мкА** в глубоком сне на всю плату.
0.2 мкА из них по даташиту забирает чип, остальное — LDO и обвязка. Методика
и приём с перемычкой на амперметре — в [HARDWARE.md](HARDWARE.md).

`Board_Init()` раздаёт всем незанятым ножкам опору:

| Ножки | Режим | Почему |
|---|---|---|
| PA4, PA5, PB12, PB13 | `GPIO_ModeIN_PD` | свободны, выведены на гребёнку |
| PB23 | `GPIO_ModeIN_PU` | кнопка K1 на землю, не используется |
| PA9 | `GPIO_ModeIN_PU` в сборке без `DEBUG` | иначе оставалась висеть |

Подтяжка, а не выход в ноль: ножки на гребёнке, случайное касание земли
выходом было бы коротким, а через подтяжку ток не течёт вообще, пока к ножке
ничего не подключено.

Отдельной возни перед сном не нужно: домен ввода-вывода в Shutdown остаётся
под питанием, ножки держат последнее состояние. Ровно поэтому `Board_Sleep()`
гасит рабочие ножки вручную — мотор, пищалку, питание потенциометра, ключ
делителя, светодиод.

**Не трогаем:** PB14/PB15 (SWD), PA10/PA11 (кварц 32768) и **PB10/PB11 — линии
USB, через которые идёт прошивка по ISP**. Эти два пина принадлежат загрузчику
и хосту, приложение их не настраивает.

У PA12 и PA14 сквозного тока нет по другой причине: цифровой приёмник на них
выключен совсем через `GPIOAGPPCfg(ENABLE, ANALOG_IE_MASK)`. Это самый чистый
способ, но доступен только ножкам с каналом АЦП. Осторожно с именами: бит
`..._IE` работает наоборот, единица **запрещает** цифровой вход.

Разбор по ножкам и таблица распиновки — в [HARDWARE.md](HARDWARE.md).

Проект **не компилировался** после удаления регулятора. Имена регистров и

## Звуковые сигналы

Пищалка на PB4. Тон — инверсия ножки в прерывании TMR1, не PWMX (у того
делитель тактовой общий на все каналы, а один уже занят мотором).

| Событие | Сигнал |
|---|---|
| Пуск | восходящая трель 1000 → 1500 Гц |
| Стоп | нисходящая 1500 → 1000 Гц |
| Настройки сохранены | 2000 → 2600 Гц, коротко |
| Сработал `max_run_s` | 1200 Гц, одиночный |
| Сработал `vbat_min_mv` | два низких 600 Гц |

Мелодии лежат в `buzzer.c` как `const buz_note_t[]`, добавляются одной
строкой. `freq = 0` — пауза. Длительности отсчитываются тиком задачи, шаг
10 мс.
